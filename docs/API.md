# WellOra Backend API — Frontend Integration Guide

Base URL: `{APP_URL}/api/v1` (e.g. `http://localhost:3000/api/v1`).
All bodies and responses are JSON. Errors are always `{ "error": "<message>" }`
with HTTP status codes (400 validation, 401 proof required, 403 forbidden,
404 not found, 409 state conflict, 410 expired, 503 unavailable).

Key terms: `device_fingerprint` = stable per-device ID generated by the app
(any opaque string). `push_token` = FCM registration token (optional until
push is wired). All timestamps ISO 8601.

---

## 1. Kit lifecycle (statuses)

`not_activated → activated → transporting → testing_in_progress → results_ready`
Only `results_ready` is manual (lab report). Frontend drives it via §3–§7.

## 2. Manufacture (seed inventory)

### POST /kits/manufacture
```jsonc
// request
{ "kit_type_slug": "urinalysis" | "fecalysis" | "oral",
  "quantity": 5, "qr_prefix": "WELLORA",           // or explicit:
  // "qr_payloads": ["WELLORA-..."],               // idempotent retry
  "expires_at": "2027-10-07T00:00:00Z" }
// 201 response
{ "created": 5, "skipped": 0,
  "kits": [{ "id": "uuid", "qr_payload": "WELLORA-…", "status": "not_activated", ... }] }
```

## 3. Auth (no SMS — device trust)

### POST /auth/register
`{ "mobile": "+639…" }` → `200|201 { "patient_id", "mobile", "created": true|false }`

### POST /auth/device — login
```jsonc
// request
{ "mobile": "+639…", "device_fingerprint": "PHONE-1", "push_token": "…?" }
// 200 known/first-touch (first touch auto-trusts)
{ "status": "active", "patient_id": "uuid", "session_id": "uuid",
  "refresh_token": "<opaque>", "expires_at": "…" }
// 202 unknown device — approval created, code shown on THIS device
{ "status": "pending", "approval_id": "uuid", "code": "482913", "expires_at": "…" }
```

### POST /auth/refresh
`{ "session_id": "uuid", "refresh_token": "<opaque>" }` →
`200 { "session_id", "refresh_token": "<rotated>", "expires_at" }` (401 if bad/expired)

## 4. Activation + approvals

### POST /kits/resolve — scan QR first, always
```jsonc
// request
{ "qr_payload": "WELLORA-…", "mobile": "+639…", "device_fingerprint": "PHONE-1",
  "push_token": "…?", "consent_version": "v1",           // required only for unknown-device path
  "basic_info": { "age": 30 } }
// responses (200 unless noted)
{ "action": "tracking", "kit_id": "uuid", "status": "activated|…" }  // already active: go to tracking
{ "action": "expired", "kit_id": "uuid" }                             // past expiry
{ "action": "need_consent", "kit_id": "uuid", "auto_trusted": true? } // known (or just auto-trusted) device
// 201 unknown device (consent_version required, else 400):
{ "action": "need_approval", "kit_id": "uuid", "approval_id": "uuid",
  "code": "482913", "expires_at": "…" }   // show code on THIS (requesting) screen
// 404 { "error": "kit not found" }
```

### POST /kits/:id/activate — known devices only
```jsonc
// request
{ "mobile": "+639…", "device_fingerprint": "PHONE-1",
  "consent_version": "v1", "basic_info": { "age": 30 } }
// responses
{ "action": "activated", "kit_id": "uuid" }                            // 200
{ "action": "tracking", "kit_id": "uuid", "status": "…" }              // already active: idempotent
{ "action": "expired", "kit_id": "uuid" }                              // 410
// 401 { "error": "approval_required: unknown device, resolve for approval first" }
// 400 consent_version missing
```

### Approvals (trusted device side)
```http
GET  /approvals/pending?mobile=+639…          // metadata only, NEVER codes
// → 200 { "approvals": [{ "id", "kit_id", "requesting_device_fingerprint",
//      "consent_version", "status", "expires_at", "created_at" }] }

POST /approvals/:id/approve                   // trusted device enters code from requesting screen
// { "mobile", "device_fingerprint": "<must equal trusted>", "code": "482913" }
// → 200 { "status": "approved", "approval_id", "kit_id", "kit_status": "activated"|… }
// 400 code missing · 401 wrong code · 403 not the trusted device ·
// 409 already approved|denied · 410 expired · 404 unknown

POST /approvals/:id/deny                      // { "mobile", "device_fingerprint" (trusted) }
// → 200 { "status": "denied", "approval_id" }

GET  /approvals/:id?device_fingerprint=PHONE-2 // requesting-device polling (code hash stripped)
// → 200 { "id", "kit_id", "patient_id", "requesting_device_fingerprint",
//         "status": "pending|approved|denied|expired", ... } (auto-marks expired)
```

**Approval UX pattern:** requesting screen shows `code` + polls `GET /approvals/:id`
until `approved` (then proceed — device is now trusted, call `/auth/device` for a
session). Trusted side polls `GET /approvals/pending` (or FCM later) and approves
by typing the shown code. No blind-approve exists.

## 5. Ordering

### GET /catalog
`200 { "catalog": [{ "id", "slug", "name", "individual_price", "bulk_price", "bulk_min_qty" }] }`

### GET /labs?lat=..&lng=.. — availability feed (drive the disable UI)
```jsonc
{ "labs": [{ "id", "name", "address", "lat", "lng",
  "used_today": 1, "remaining": 0,      // null = unlimited quota
  "is_available": false,                 // disable selection when false (advisory)
  "distance_km": 10.618, "geojson": { "type": "Point", "coordinates": [121.03, 14.65] } }] }
// nearest-first; without lat/lng returns plain list (distance_km/geojson null)
```

### POST /orders
```jsonc
// request
{ "mobile": "+639…", "kit_type_slug": "oral", "quantity": 2,
  "assignment_mode": "auto",            // or "manual" + "lab_id"
  "delivery_method": "pickup" | "shipped", "lat": 14.6, "lng": 121.0 }
// 201 response
{ "order": { "id": "uuid", "assigned_lab_id": "uuid", "assignment_mode": "auto",
    "delivery_method": "pickup", "delivery_fee": 0, "payment_status": "initiated",
    "total_amount": 698 },
  "kits": [{ "id": "uuid", "qr_payload": "WELLORA-…" }],  // specific pre-printed QRs
  "quota_warning": false }   // true = lab may be full at dispatch (advisory; reroute covers it)
// 400 bad input/unknown lab · 409 insufficient inventory (+ order_id) · 503 no labs
```

### GET /orders/:id
`200 { "order", "lab": { "id", "name" }, "kits": [{ "id", "qr_payload", "status" }] }` · 404

## 6. Transport

```http
POST /kits/:id/dropoff-confirm     // { "clinic_id": "uuid"? } (clinic confirms receipt)
POST /kits/:id/pickup-collected    // (collection event, no body needed)
```
Both: `activated → transporting`, set `return_method`, consume the lab's
dispatch-day quota slot (or auto-reroute, see below).
```jsonc
// 200 response (both)
{ "kit_id": "uuid", "status": "transporting",
  "dispatch": { "lab_id": "uuid", "quota": "consumed" } }
// rerouted (assigned lab full): { "quota": "rerouted", "rerouted_from": "uuid", "lab_id": "uuid" }
// all labs full:                { "quota": "exhausted", "lab_id": "uuid" } (kit stays transporting)
// retry:                        { "dispatch": null } (no double-consume)
// 404 unknown kit · 409 must be activated (with current status)
```

### POST /kits/:id/lab-arrived — `transporting → testing_in_progress`
`{ "lab_id": "uuid"? }` (uses assigned lab if omitted; mismatch → 409) →
`200 { "kit_id", "status": "testing_in_progress", "lab_id" }`

### GET /kits/:id/track
```jsonc
{ "kit": { "id", "qr_payload", "status", "return_method", "assigned_lab_id", ... },
  "lab": { "id", "name" } | null,
  "report": { "id", "file_type", "uploaded_at" } | null,
  "timeline": [{ "from_status", "to_status", "trigger", "actor_role", "created_at" }] }
// 404 unknown kit
```

## 7. Lab reporting (only manual transition)

### POST /kits/:id/report
```jsonc
// request
{ "lab_id": "uuid", "file_url": "https://…", "file_type": "image" | "pdf",
  "uploaded_by": "tech-1?" }
// 201 { "kit_id": "uuid", "status": "results_ready" }
// 200 { "kit_id", "status": "results_ready", "duplicate": true } (idempotent retry)
// 409 must be testing_in_progress · 400 bad file payload · 404 unknown kit
// NOTE: file_url accepted as-is; Supabase Storage upload wiring is pending.
```

## 8. Clinics + ratings

```http
GET /clinics?lat=..&lng=..    // like /labs: nearest-first + distance_m + Mapbox geojson
```

### POST /kits/:id/rating — one per completed kit
`{ "mobile": "+639…", "score": 1..5, "comment": "…?" }` →
`201 { "rating": { "id", "kit_id", "lab_id", "patient_id", "score", ... } }`
(lab/patient derived from kit; 409 non-completed or already-rated; 403 non-owner; 400 bad score)

### GET /labs/:id/ratings
`200 { "lab", "count": 1, "avg_score": 5, "distribution": [{ "score": 1..5, "count" }] }`

## 10. Happy-path sequences

**Activate (new patient):** `register → device-login (auto-trust, session) →`
scan `resolve → need_consent → activate` → `track`.
**Activate (new device):** `resolve (+consent) → need_approval [show code] →`
trusted side `pending → approve(code) → approved` → requester poll sees it →
`device-login → session`.
**Order → deliver:** `catalog → labs (disable unavailable) → orders →`
activate kit → `dropoff-confirm|pickup-collected → lab-arrived → report →`
`rating`. **Lab app:** scan QR via `resolve` (returns `tracking` + `kit_id`) →
arrive → attach report.

## 11. Mapbox notes

`geojson.coordinates` are `[lng, lat]` — pass directly to
`mapboxgl.Marker.setLngLat()` or a GeoJSON source. Raw `location` column values
are opaque EWKB hex (typed `string`, ignore them). Needs a Mapbox public token
on the frontend; backend supplies only coordinates.
